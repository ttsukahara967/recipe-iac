# 2026-10-23: Backend base image Python 3.12 -> 3.14

## Why

- The backend ran on `python:3.12-slim`, but the image cached locally (and pushed to ECR) was 3.12.14.
  `docker build` keeps using a cached base image unless `--pull` is given, so patch releases were never picked up.
- 3.12 is in security-fix-only mode. 3.14 has been stable for a year, so library support is mature.
  3.15.0 (released 2026-10-09) was skipped for now because wheels may still be missing.

## Change

`backend/Dockerfile`:

```diff
- FROM python:3.12-slim
+ FROM python:3.14-slim
```

No application code or `requirements.txt` changes.
`IMAGE_TAG` in the Makefile hashes the Dockerfile, so the next `make deploy` produces a new tag and ECS rolls the tasks.

## Steps

1. Recorded the baseline on the running 3.12 container (table below).
2. Switched the base image and ran `docker compose build backend`.
   It succeeded on the slim image, which has no C compiler, so every C extension installed from a prebuilt cp314 wheel.
3. Ran `make local-up` and checked the API and frontend (table below).
4. Restarted the backend to re-run the startup seed upsert. No warnings, errors or tracebacks in the logs.

The last three are transitive dependencies and are not pinned, so they float to the latest release on every build.
This is not a problem now, but a lock file (for example `pip-compile` output) would make builds reproducible.

## Deploy to develop

1. Ran `make deploy ENV=develop`.
   The first attempt failed at `tf-init` with "No valid credential sources found" because `AWS_PROFILE` was not set.
   Nothing had been changed at that point. Re-ran with `AWS_PROFILE=recipe-iac make deploy ENV=develop`.
2. The frontend was unchanged. The backend pushed `recipe-iac/api:12255f6cdbd5`.
   Terraform reported `1 added, 1 changed, 1 destroyed`: the task definition was replaced (revision 49) and the service updated.
3. Ran `aws ecs wait services-stable`.
   Afterwards only the PRIMARY deployment was left, with one task running the new image.
4. The CloudWatch log group `/ecs/recipe-iac-develop-api` showed `Application startup complete.` and no tracebacks or errors.
5. Repeated the checks against `https://api.develop.ouchirecipes.com` and `https://develop.ouchirecipes.com`.
